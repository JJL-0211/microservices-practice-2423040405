项目名称：Kitty 主题女性垂类内容带货电商系统

目标用户：18-60 岁女性

优先实现：C 端用户购物端

核心模型：内容种草，商品交易

## 第 04 周：核心业务流程与业务建模

### 1. 本周实现的一条核心业务流程：商品下单流程

从内容种草进入商品后，用户完成一次下单的完整链路：

浏览商品列表 → 查看商品详情 → 提交订单（触发业务规则校验）→ 校验通过后生成订单并扣减库存 → 查询订单结果。

对应接口：`GET /api/products`、`GET /api/products/{id}`、`POST /api/orders`、`GET /api/orders/{id}`。

### 2. 参与该流程的业务实体及其关系

| 实体 | 说明 |
| --- | --- |
| 商品 `Product` | 内容挂载的、可被下单的商品，含名称、分类、单价、库存、是否上架 |
| 订单 `ShopOrder` | 一次下单行为的记录，含订单号、所购商品、数量、金额、状态、下单时间 |

关系：**一个商品可以被多个订单购买，一个订单只对应一个商品，即商品 1 : N 订单**（订单持有多对一引用 `product_id`）。

### 3. 需要在 Service 中检查的业务规则（1 条）

**下单业务规则**：用户提交订单时，商品必须存在且处于"上架"状态，购买数量在 1~5 件之间，且库存必须充足；校验通过后按 `单价 × 数量` 计算订单金额并扣减库存，防止超卖。

在 `OrderService.createOrder` 中实现，违反规则的响应：数量超限 → 400；商品不存在 → 404；商品下架 / 库存不足 → 409。
